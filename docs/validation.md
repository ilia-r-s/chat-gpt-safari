# Validation

## Development build 0.2.0 (4)

The November 18, 2026 verification includes 90 JavaScript tests, 30 native XCTest cases, isolated Chrome panel and DOM checks, a 320-pixel system WebKit panel check, SwiftUI rendering and native MCP discovery. The unsigned macOS app and embedded extension build in Debug and Release. The Release archive contains Intel and Apple Silicon executables.

The panel was compared with OpenAI’s published side-chat illustration. The behavioral checks use local pages, simulated provider replies and inert account fixtures. System WebKit exercises the installed rendering engine in an ephemeral WKWebView. Signed Safari extension routing, real account access and live provider behavior require the installation checks below. [Official design reference](https://learn.chatgpt.com/docs/chrome-extension)

## Automated coverage

Run `./scripts/check.sh` for syntax/manifest resource checks, JavaScript unit/integration tests, native XCTest cases, and Xcode/plist validation. Coverage includes:

- Bounded complete-turn context, newest-source deduplication, Unicode estimates, invalid URLs, and settings limits.
- UTF-8/CRLF/multiline SSE framing, partial/failed/incomplete responses, cancellation, invalid data, and admission errors. Completed streamed tool/message items survive a metadata-only terminal event within bounded storage; failed or interrupted streams never authorize their calls. Completion-only text appears, and empty final responses fail visibly without repeating actions.
- Public API request contract, tool-loop limits, encrypted reasoning continuity, no silent fallback billing, unknown tools and exhausted round limits. Every ordinary chat receives browser tools, including when an obsolete disabled mode is present in stored settings.
- Reasoning capability discovery, exact documented model fallbacks, unknown models, unavailable overrides rejected before inference, and the sending panel's effort retained across rounds. Opt-in public web search uses its documented request shape, reports activity, retains separate browser-action approvals, and does not retry provider rejection. Valid URL citations persist as clickable links; malformed/unsafe annotations and overlaps are rejected.
- Same-name UTF-8 files retain separate IDs, indentation, tabs, line endings and literal replacement characters. Invalid bytes are rejected. Excerpt trimming accounts for both JSON encoding layers and preserves Unicode character boundaries.
- Partial settings patches merge serially without resetting unrelated preferences or desktop consent. Text-file batches respect type, count, size, encoding and truncation bounds.
- User approvals, stale references/navigation, per-origin read consent, forbidden URL schemes, tab opening/navigation/closure, and blocking changes after cancellation during approval or the final tab check. Embedded chat cannot explicitly navigate or close its own tab.
- Desktop approvals route to the originating request, require matching session/request/approval IDs, and stop on denial, cancellation, account changes, opt-out, or cleanup. Panel RPC cannot forward desktop relay requests. Native leases bind to the OS-provided Safari profile and expire; the loopback parser rejects wrong secrets/hosts, browser origins, ambiguous lengths, oversized bodies, and extra bytes. Only an accepted literal boolean can authorize an MCP action.
- Safari-style per-frame script errors preserve concrete read/action failures; failed actions invalidate their prior snapshots. Gallery navigation tolerates autoplay selection changes but still rejects modified destinations, ambiguous selections, forms and stale controls; visible offers remain separately clickable.
- A pending sidebar or desktop approval is invalidated when an account changes and changes back. Background tests cover both an arriving native notification and a missed notification caught by the dispatch-time generation check. A delayed response forks if another editor advances its base revision.
- Concurrent draft changes preserve both editors, including a follow-up typed while a reply streams. Stale clears and late saves after deletion are covered. Legacy histories and named key connections retain their owners during explicit key replacement.
- Native revocation tests exercise same-issuer discovery, form encoding, retry, offline failure and an untrusted endpoint using an injected transport. The desktop opt-in preflight is exercised without writing to Keychain.
- Context-menu, dock restoration and typed-mention checks confirm that listing tabs and remounting the panel do not read pages. Caption fixtures validate displayed tracks, timestamps, bounds and the selection-only path.
- The classic background registers synchronously and authenticates privileged senders. Streamed replies commit through the background.
- Status text survives UTF-8 and Windows-1252 decoding of the classic background script. The regression reproduced `Thinkingâ€¦` before the fix; background builds now require ASCII source with Unicode escapes for special characters.
- Missing companion/temporary-extension setup, fixed native launch/sign-in routes without credential exposure or custom-scheme browser tabs, and resolution restricted to the native handler's own containing app, including customized bundle identifiers and unreadable/unregistered Xcode build locations. The automatic sign-in URL rejects paths, parameters, fragments, and alternate actions.
- Safe Markdown rendering, per-account history, chat-count limits, and storage-byte bounds.
- Edit/retry branches preserve original turns and attachments, exclude superseded replies, and validate revised input. Composer tests cover UTF-8 byte bounds, aggregate/count limits, account ownership, active-chat pointers, draft-only history, deletion, and cleanup races.
- Cleanup write barriers, late responses after erasure, retryable failures, scoped native deletion, symlink protection, and directory locking without files. No tests erase actual user data or Keychain items.
- OAuth PKCE RFC vector, dynamic/returning registration, exact callback matching, duplicate/state/host/expiry checks, form encoding, loopback request validation.
- ES256 and RS256 signature verification, tampered/unsigned tokens, wrong issuer/audience/nonce, expired claims, and missing plan permission.

`tests/ui-smoke.mjs` exercises the real panel DOM with a simulated browser/native transport, and executes content helpers against a real browser DOM. It checks missing-companion handling, automatic sign-in dispatch, setup retry, one chat interface without a mode gate or automatic page reads, keyboard-operable attachment menus, searchable multi-tab selection, partial-read failure/retry, files/drop, web-search controls and persisted citation links, effort controls, action status, consecutive streamed turns, cancellation, escaped model HTML, draft restoration, account switching, edit/retry, failed saves, popout, keyboard composition, history search, narrow layout, and cleanup. A delayed tab batch cannot continue after account changes even when the new account reopens the picker. Theme checks cover immediate preview, ordered rapid changes, slow/failed saves, stale bootstrap replies, updates from other panels, switching during a response, and system appearance. Screenshots are saved under `build/screenshots/`.

DOM checks cover text filling/events, dropdowns, checkbox/radio state, page/region scrolling and boundaries, `overflow:hidden` versus `clip`, textless strips, RTL scrolling, transformed galleries with duplicated site tab IDs, carousel selection changes during approval, ambiguous selections and changed destinations, hidden/disabled controls, sensitive fields, changed link targets, rejected writes, and bounded metadata. A provider simulation runs the actual agent, SSE decoder, approval executor and DOM helpers through read → page scroll → verification read → reply without an attachment or browser-mode setting, even when earlier conversation text claims browser actions are unavailable; it verifies real DOM movement and refusal to execute a failed stream's pending call.

A separate isolated replay of Apple's public homepage markup, stylesheet and shared gallery JavaScript initializes both entertainment strips and advances each from item 0 to item 1 through its own navigation tabs. A second replay changes the selection after the snapshot and confirms that an approved left action takes both real strips from item 1 back to item 0, with no script errors. External networking is blocked during replay. This checks actual gallery behavior beyond the synthetic fixtures, but is not a live Safari or model-driven website test.

After building, `./scripts/node.sh tests/mcp-smoke.mjs` launches the actual native executable in stdio mode, discovers all ten tools, and verifies that clients without form elicitation are refused before Keychain or Safari access. This is a protocol test, not a desktop handoff test. `python3 scripts/package-desktop-plugin.py` prepares the local marketplace and plugin ZIP without registering or installing them.

The dock fixture also checks real page reflow, fixed headers while scrolling, floating and newly added controls, typing/clicking beside chat, window resizing, reduced action-read bounds, repeated opening without duplicate frames, narrow-window fallback, and layout/focus restoration on close or host removal. Resize coverage uses real pointer/keyboard input: wide/narrow limits, preserving drafts and the iframe, smaller window clamping, Home/End and arrow keys, Escape cancellation, Enter/double-click reset, and remembering width across reopening. Screenshots are `build/screenshots/panel-docked.png` and `panel-resized.png`. These fixture checks do not establish compatibility with every live website in Safari.

`./scripts/preview-app.sh` renders six production SwiftUI states with inert data, including separate named and legacy key connections, a saved OAuth account, a compact window during sign-in, and an API-key connection error. It also checks a production view inside an AppKit window while changing Light → Dark → System and reversing those choices, verifying rendered colors and clearing the window override. The earlier SwiftUI-only approach reproduced a stuck explicit theme in this test. It does not instantiate `AppModel` or access Keychain, OAuth, Safari, or user preferences. Screenshots (`app-*.png`) were inspected for wrapping, contrast, status placement, and controls. This does not replace live OS-appearance changes, VoiceOver, keyboard, native-window, or sign-in testing.

A read-only installation probe found that Launch Services omitted the Xcode containing app while listing older unsigned copies. A separate sandboxed probe denied file reads of that containing app: parent bundle metadata became unavailable, but the revised containment-based lookup still returned the exact app path. It did not launch the app or access accounts. The actual signed extension-to-app launch remains a manual integration check.

`./scripts/build.sh` compiles both app and extension. `./scripts/package.sh` builds the optimized unsigned Release artifact. Apple's converter is also used to verify Safari manifest compatibility; its temporary projects stay under `build/`.

## Still requires a signed Safari installation and live account

These checks cannot be inferred from passing unit tests or an unsigned build:

1. Enable the actual extension in Safari; open/close the panel on HTTPS, HTTP, restricted pages, and sites with strict CSP. Verify toolbar shortcut and selection context menu. Test Continue with ChatGPT with the companion closed, already running, and with its window closed; ensure browser sign-in starts without a separate setup click and completion/errors reach the panel. Test the temporary folder installation's setup guidance separately.
2. Grant/deny website access; verify cross-origin frames and inaccessible tabs fail clearly. Exercise a navigation while an approval is visible.
3. Complete ChatGPT sign-in, decline plan permission, reconnect, refresh an expiring token, switch away and back during approval, and check the reported revocation outcome at sign-out. Add two API-key connections and replace one key while both panels are open. Confirm shared Keychain/App Groups access with real provisioning.
4. Verify live Responses output/model catalog, supported effort choices, hosted web search/citations, and usage-limit errors for an eligible ChatGPT account; separately test API-key billing. Ask for page and nested-gallery scrolling without attaching the originating page, then verify the read/action approvals, visible movement and final reply.
5. Exercise native callback timeout/cancellation, sleep/wake, extension background suspension, closing a streaming panel, and Safari restart.
6. Inspect native onboarding layout, permissions and account switching in Safari profiles/private windows. Check VoiceOver/keyboard navigation.
7. Sign/notarize a release and test installation on a separate Mac with no development tools installed.
8. Test erasure in every Safari profile, native Keychain deletion, app quit, failure recovery, and reinstall with a signed build. Inspect only the app's own containers and compare the documented footprint; do not infer zero-trace removal from unit tests.
9. Install the local desktop plugin in a compatible ChatGPT Work/Codex thread. Verify the signed native port, loopback replies, every tool, approval/decline/cancellation in ChatGPT, permission denial in Safari, account/profile changes, timeout, cleanup, and restart. Confirm a second profile cannot duplicate an action. Regular ChatGPT remote control has no deployment in this package and is not covered by this local plugin test.

This verification used fixture credentials. The packaged development artifact is unsigned.
