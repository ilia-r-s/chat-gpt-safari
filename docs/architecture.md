# Architecture

## Runtime boundaries

1. **SwiftUI app** handles onboarding, account selection, API-key entry, and browser-hosted OAuth. A temporary Network.framework listener binds only to `127.0.0.1`, validates the callback host/path/state, and closes after one callback or ten minutes. The exact callback URI is used for the code exchange. OpenAI's public signing keys validate identity before credentials are committed.
2. **Native Safari extension** handles a fixed allowlist of native messages. Shared Keychain holds the protected vault; a lock on the App Group directory serializes updates without creating a lock file. Reads do not open the group container. The background script receives a short-lived bearer credential only when needed. Refresh tokens and API-key input never appear in the page or panel UI.
3. **Background script** owns inference, account-scoped storage and browser capabilities. The panel submits a turn with its base revision. The background commits the final or interrupted answer and returns its saved ID and revision. It accepts messages only from the exact extension panel URL and extension ID. Native credential replies are never forwarded through the panel's RPC. Requests use the public Responses API, omit browser cookies, reject redirects, and never use private ChatGPT endpoints.
4. **Panel** owns the current view and unsent editor. The dock and standalone window use the same panel. Their editors can diverge, and neither receives credentials.
5. **Content helpers** run in Safari's isolated world. Page extraction skips hidden text, scripts, controls' values, and editable fields. An extension-origin iframe isolates the chat UI from website styles/scripts. HTML output is escaped before a small Markdown subset is rendered. There is no page-to-native `postMessage` bridge.

**Continue with ChatGPT** sends the fixed `auth.signin` native request. The native handler resolves the containing app from its own OS-loaded class bundle, requiring the expected native extension identifier suffix and `app/Contents/PlugIns/appex` nesting. It does not read the parent's Info.plist (which can be inaccessible in the extension sandbox) or choose a duplicate build through Launch Services. It delivers the fixed `safarichat://signin` action directly to that containing app through `NSWorkspace`, without activation or a recent item. The app starts browser OAuth automatically and pushes completion/failure back over Safari's native port; focus refresh remains a fallback. No caller-supplied URL, callback, or app path is accepted, and no custom-scheme Safari tab is opened. `app.open` remains for account management and API-key entry. Temporary folder installations have no native helper and show setup guidance.

Native setup uses a credential-free presentation view, with all account actions dispatched to `AppModel`. Its System/Light/Dark preference lives in the app's sandbox preferences and is included in native cleanup; Safari profile themes remain independent. An AppKit window appearance adapter applies explicit choices and clears the override for System; it avoids SwiftUI retaining the previous explicit scheme. A saved-account badge describes locally retained state, not a live token validation. The window can resize and scroll without clipping account details or status messages.

Panel appearance applies synchronously, with ordered patch saves and revision checks against stale bootstrap replies. Storage changes update other panels immediately. Save failures retain the current preview and show a retryable error. Preference patches merge inside the cleanup write barrier, preserving unrelated settings and desktop consent. Cleanup invalidates pending UI saves.

## Context and runtime efficiency

- Default budget: 12,000 characters per page, 48,000 input characters, eight recent turns, six browser-tool rounds. These are character budgets, not exact token counts; serialization/schema overhead is separately bounded. The UI labels pre-request token numbers as estimates; provider-reported usage is shown after responses.
- Only explicit attachments enter the prompt. Newest snapshots replace earlier snapshots of the same source. Older complete turns are removed before newer turns. Sources remain untrusted user data, separate from assistant instructions. URLs omit query/fragment values in model context.
- Extraction stops at its character budget or 20,000 visited text nodes and returns at most 50 controls (including up to four carousels) and 10 native scroll regions, with control metadata bounded to 5,000 serialized characters. Action reads focus on the viewport; explicit page attachments prefer article text. Dropdown option previews are bounded, and field values remain excluded. No screenshots, whole DOM dumps, automatic tab sweeps, embeddings, or paid summarization calls.
- One compact namespaced browser function; no parallel browser calls. Every API request has `store: false` and `stream: true`. Reasoning continuity is carried as encrypted output only inside an active bounded tool loop.
- Model catalogs cache for five minutes per native session generation. An explicit reasoning effort is checked against advertised catalog capabilities, falling back only to documented exact model IDs and dated snapshots; unknown variants expose Auto only. Auto omits `reasoning.effort`. The initiating panel sends its current choice, and every round retains it. Unsupported overrides fail before inference. The saved preference is local to the Safari profile.
- UTF-8 stream decoding is incremental. Finished output items are retained within 64 indices and a one-million-character bound when a terminal event omits its output. They are used only after successful completion, never after failure/interruption. Completion-only message text/refusals are recovered when no text delta arrived; reasoning is not rendered. A response with no reply or tool call reports an error instead of completing an empty bubble; actions are never retried automatically. The UI paints at most once per animation frame and parses Markdown at completion. The output-size limit is 120,000 characters. A task expires after five minutes, including approval wait time.
- Web search is explicitly enabled and independent of Safari actions. Requests add the public `web_search` hosted tool within the same round limit; unsupported models/accounts report the provider error. Up to 40 validated HTTP(S) URL citations become escaped Markdown links in the completed answer and local history. Citation URLs with embedded credentials or unsafe schemes, and malformed annotation ranges, are excluded; no alternate billing path is attempted.
- The classic background bundle is ASCII with JavaScript Unicode escapes for special characters, so its status/approval text is independent of Safari's script decoding. API response streams and user content retain their Unicode text.
- History is limited to 50 chats, 80 messages per chat, approximately 400 KB per chat, and 4 MB total. Old chats are evicted before a write hits the extension quota. No background polling, third-party analytics, fonts, UI framework, or runtime libraries.
- Composer drafts are separate account-checked records: at most 20 drafts, 200 KB each and 600 KB total, with up to six bounded attachments. At most 50 small account/source-tab pointers restore the active chat. Draft writes debounce for 300 ms and flush before explicit chat switches, popout, and close; unchanged panels do not repeatedly rewrite their drafts. Forced termination can lose the latest unsaved keystrokes. Old drafts are evicted first, and oversized saved excerpts are marked as trimmed.
- The **+** menu and typed `@` picker use the same explicit attachment path. Up to 200 accessible tab titles/addresses can be searched locally. The background reads only selected tabs. File input/drop/paste validates UTF-8 bytes, assigns an opaque identity per picked file, and preserves whitespace in the request and local storage. Both layers of JSON escaping count toward the model input budget.
- Full-page attachments capture text without replacing active browser-action references. They can use half the excerpt budget for timestamped cues from one already-displayed caption track on a visible video. Selection-only attachment reads the selection directly. Context-menu excerpts are staged for a single composer, expire for delivery after five minutes, and carry the originating session generation.
- Saved chats have monotonically increasing revisions. A legacy saved chat starts at revision 1. Divergent writes create separate copies and a retry of the same write can reuse its saved copy. Draft conflicts copy the draft and corresponding bounded history in one storage write. Late writes to a deleted saved conversation fail. The background serializes these decisions with deletion and cleanup.
- Message editing and retries create a new chat containing the selected user turn and its predecessors. Superseded replies and later turns are excluded. Original conversations remain in bounded local history; original unsent drafts stay attached to their source chat. Existing browser-action approvals still apply to a retried request.

## Permission model

The manifest requests `activeTab`, scripting, storage, context menus, native messaging, and the public API host. Other websites are optional. Safari grants website access after an explicit toolbar gesture. The tab picker shows only accessible tabs; this preview does not silently request access to all websites. Safari tools are advertised in every chat within the bounded tool loop; there is no browser-mode preference or request gate. Merely opening chat does not read a page. Each run carries the sending panel's search choice. A null tool tab ID resolves to the originating tab from the trusted panel URL, but still needs normal read/action approvals; no page text enters the request automatically. Attached page metadata includes its tab ID for explicit targeting. Per-request instructions describe the tools available now, so earlier assistant statements about missing capabilities do not define the current tool set.

Attaching a page authorizes its context for the current message. Tool reads of a new website require approval, and read consent is scoped to the tab **and origin**. Click/fill/select/check/scroll/navigation/close/open operations require approval. A fresh read provides opaque element IDs and supported actions. The executor rechecks URL, node connectivity, label, control type, link/form destination, visibility, and sensitive-field status immediately before writing, and invalidates references even when a page rejects a write. Fill/select/check results verify the immediate resulting control state; clicks require a fresh read to verify the page outcome. Password, payment, file-upload and token fields are excluded. Website JavaScript can still mutate a DOM between checks or asynchronously afterward; this is a DOM tool, not a CDP debugger or a guaranteed transaction.

Safari unloads the iframe on full navigation. The background remembers explicitly docked tab IDs in memory. When an accessible web page finishes loading in one of those tabs, the helper remounts the dock without focusing it or reading its contents. Closing a dock, removing its tab or erasing data clears its entry. Background suspension can discard that memory. A standalone panel stays open for an uninterrupted multi-page task. A browser crash or forced termination can lose the newest unfinished output.

Scroll reads expose available axes for native overflow containers, including programmatically scrollable `overflow:hidden` and image-only strips; `overflow:clip` is excluded. Transform-based carousels use their own ARIA tabs only when a bounded scan finds a gallery/carousel ancestor, matching tabpanels, and exactly one selected item. Gallery navigation is listed ahead of ordinary controls so long link lists cannot crowd it out. Same-document fragment tabs and non-form buttons are eligible; product links are never substituted for scrolling, but remain available for explicitly requested clicks. Approval names the gallery and direction. Execution rechecks controls, order, destinations, labels, panels, and visibility, then chooses the adjacent item from the live unique selection. This tolerates autoplay while approval is pending without accepting changed destinations or ambiguous selection; ordinary element clicks retain their full stale-state checks. Dispatch reports the starting/requested item without claiming the animation completed; the model must read again. Arbitrary drag-only/canvas galleries and undocumented site-specific script APIs are not supported.

Script injection handles both rejected promises and per-frame `InjectionResult.error` values. Read and action errors are bounded and passed to the model/UI, rather than replacing every thrown page-helper error with a generic missing-result message. A failed write still invalidates its previous snapshot. See [the documented injection error contract](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/scripting/executeScript#return_value).

The panel docks in a closed shadow root and uses a manual popover to stay outside page stacking/transform contexts. While open, a right-hand gutter reflows ordinary page content. Its accessible left-edge separator uses pointer capture and keyboard controls to resize within 320–840 pixels, leaving at least 320 pixels for the page when possible. Width stays in the isolated content helper's memory until navigation/reload, with no storage writes. Reset restores the adaptive default; cancelling a drag restores its starting width. The iframe stays mounted so resizing preserves chat/draft state. A bounded scan (5,000 elements, up to 80 fixed controls) keeps common fixed headers and floating controls within the remaining page area. Layout refreshes follow animation-frame-coalesced resizing and debounced DOM/style changes; no polling runs. Only owned inline properties are restored on close, page removal, or navigation, preserving newer site changes, form values, and focus. Action reads and horizontal scrolling use the reduced visible width. Windows below 720 pixels use the standalone fallback when opening chat. This does not change the real browser viewport, `window.innerWidth`, or viewport-based media queries, and cannot adapt every site layout.

## Optional desktop control

The local MCP plugin launches the signed app executable with `--mcp`, bypassing SwiftUI setup. It exposes ten explicit Safari tools over newline-delimited JSON-RPC on stdio. It uses no third-party runtime, launch agent, daemon installation, or public listener. A native loopback inbox binds only to `127.0.0.1`; a random routing secret and one-hour lease live in the existing app-specific Keychain vault. Messages and excerpts stay in memory. At most four leases and four background sessions are allowed; each action, including approval, has a five-minute deadline.

Safari's native port receives requests from the containing app. The background checks the desktop-control opt-in, native lease, account and host generation before creating a tool executor. Because app-to-extension notifications may reach multiple profiles, the native handler binds verification and replies to Safari's OS-provided profile identifier. Enabling desktop control chooses one profile in the shared vault; arbitrary pages cannot select a profile or call the relay through panel RPC.

The executor sends each required approval to its originating MCP request. The native server emits `elicitation/create` and accepts only a matching response with `action: accept` and `approve: true`. It first reads the existing desktop opt-in without creating a vault. Lease registration rechecks that profile and vault identity. The browser executor rechecks access, account and session generation after approval. A client without form elicitation is refused before connecting to the relay; it cannot fall back to sidebar approval. Desktop cancellation, sign-out, disabling access, and local cleanup abort pending work. Cleanup drains desktop replies before erasing the Keychain lease and browser storage. Late sign-in/bridge registrations must still match the original vault generation.

This provides a custom local plugin route, not OpenAI's built-in Safari/tab-mention integration. Regular ChatGPT remote conversations would need a separately authenticated remote MCP service or supported tunnel and deployment; neither is shipped here. Live desktop elicitation, signed native-port routing, profile behavior, and Safari interaction still require integration testing.

## Accounts and local data

Each OAuth registration retains its issued client ID and validated subject. Each new API-key connection has an opaque local ID. Adding keys always creates separate histories, including when the same key is entered twice. Explicit replacement keeps the chosen ID and its history. Legacy `api-key` records keep that identifier and appear as **Original API key**.

The vault generates a fresh session ID when the active credential changes, even when returning to the same connection. The native app and handler announce transitions. The background cancels superseded work and checks the generation for credential delivery, post-approval execution and final writes. The panel invalidates old editors, streams and dialogs and also checks on focus. The native account picker is shared across this app’s Safari profiles. Local history is scoped to the Safari profile and connection.

Native sign-out detaches the current connection and clears its saved tokens atomically. Only the pending revocation request retains the retiring OAuth refresh token in memory. It discovers the HTTPS revocation endpoint from the configured issuer, allows one retry for a transient failure, and reports whether revocation was confirmed. The reply cannot change a later login. API keys disconnect locally. Each account keeps its chat history until deletion or eviction. OAuth refresh is single-flight for a connection within a native process, with a conditional vault write for rotating tokens. [OpenAI session guidance](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions#end-the-renewable-session)

**Erase local data** is separate from sign-out: it stops work, drains already-started storage writes, rejects pending/new writes, clears and verifies browser storage, deletes the entire app-specific Keychain record (including registration metadata and host ID), and removes the legacy development lock file. Native cleanup touches only an allowlist of cache/preferences paths in the current process's verified sandbox container. It refuses redirected ancestors and never deletes another app's containers or Safari's databases. Existing sign-in/refresh operations must still match the original vault before writing. Cleanup failures remain visible and retryable. Finish with the companion app's **Erase native data and quit** action, then uninstall. See [data lifecycle and removal](data-lifecycle.md) for exact scope and platform limits.
