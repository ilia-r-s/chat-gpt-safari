# Chrome extension comparison

The visual references are the supplied screenshots of the Chrome extension’s Chat and Work screens, composer, model picker, open sidebar and resize grip. OpenAI’s browser extension guide documents side chat and supported browsers. The screenshots supply details the guide does not show. Safari Chat uses its own name, account connections and website permissions. [OpenAI browser extension guide](https://learn.chatgpt.com/docs/chrome-extension)

| Feature | Safari Chat 0.3.9 |
| --- | --- |
| Side chat | A resizable panel reserves space at the right of the originating tab. The toolbar reuses it. A short grip marks the draggable divider. Safari exposes the full browser viewport to website media queries and scripts. The pane stays beside the page in narrow windows. Wide content can scroll in the page column. A slow panel offers an in-place retry. When Safari blocks mounting, the toolbar explains the restriction. [Chrome side-panel API compatibility](https://raw.githubusercontent.com/mdn/browser-compat-data/main/webextensions/api/sidePanel.json) |
| Conversation and composer | An inset conversation surface has a sidebar button, centered Chat/Work switch and Temporary chat button. Chat is the initial mode. A saved Work preference reopens in Work. Both modes use the same input dimensions and share the **+** menu and model/effort pill. Files, Tabs and the account’s default browser approval selector sit above the input. Safari Chat retains its send/stop and approval controls. The sidebar opens over the conversation with a narrow icon rail, New chat, searchable Recents and Settings. |
| Longer browser tasks | Both modes default to 100 browser attempts per message. The counter resets as soon as the turn ends. A reply that exhausts the limit offers **Continue** with the next allowance. Continuous motion supports speed changes and manual stop. For ‘scroll until’, a page-side check stops at a matching carousel or phrase, a boundary, or a bounded search checkpoint while waiting for the model. |
| Page and selection | Right-click **Ask Safari Chat** to attach the selection or page for review before sending. Opening or restoring chat shares no page text. |
| Typing and text edits | Side chat can double-click a target or viewport coordinate, focus a writable field, type at the caret and press editing keys. It can select a quoted passage or range and copy, paste, delete or replace that selection. Visible ordinary text may span inline elements. Edits to a paragraph change this copy of the page and can disappear on rerender or reload. The native companion handles plain-text clipboard transfers. |
| Action pointer | A black arrow with a white edge and blue glow follows the cursor design in OpenAI’s published Chrome extension. It marks clicks and copied text and can trace a path across empty space and elements with the button up. Reduce Motion suppresses decorative transitions. The system pointer remains available. [Official Chrome extension](https://chromewebstore.google.com/detail/chatgpt/hehggadaopoacecdllhhajmbjkdcmajg) |
| Tab mentions | Type `@` or use **+ → Add browser tabs**. Listing tabs in the source window shares their available metadata. A tab whose website Safari withholds still appears by position. Choosing it can request website access in the current pane. The background verifies the destination before releasing an excerpt. |
| Navigation | On refresh and full-document navigation, the dock uses an early document hook when Safari permits it, reserves space as soon as the document root exists, reopens in the source tab and reconnects to the running turn, buffered reply, draft and pending approval. A full refresh destroys the old iframe, so there can still be a brief visual gap. Reattachment issues no model request or browser action. The source tab supplies the destination for subsequent reads, subject to website access and fresh element references. Explicitly closing chat stops the task. A browser or background restart ends live execution. |
| Files and captions | Up to six sources total. File selection, drop and paste support UTF-8 text, code and data up to 200 KB per file. Distinct same-name files keep their identities and formatting. Sharing a page can include timestamped captions already exposed by a visible video’s displayed text track. Availability on YouTube depends on its player and the page. PDF, image, audio/video uploads and hosted file management are outside this build. |
| Accounts and models | Both modes use the public Responses API and the connected account’s model list. Chat groups supported routes into GPT-6 and GPT-5.6 Sol. Its levels are Instant, Medium, High, Extra High and Pro when a corresponding route exists. GPT-6 Pro uses authorized Astra or a dedicated Pro ID. GPT-5.6 Pro uses its Sol Pro route. Work takes model names, order, advertised efforts and defaults from the connected account. Reload models requests a fresh list. The API-key model list supplies fewer fields, so known models use documented effort choices when metadata is absent. The hosted Chat router, conversation state and plan entitlements belong to ChatGPT. [ChatGPT families and levels](https://help.openai.com/en/articles/20001354-gpt-6-and-other-models-in-chatgpt) · [Sign-in inference contract](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) · [Responses reasoning mode](https://developers.openai.com/api/docs/guides/reasoning#reasoning-mode) |
| Dictate and Start Voice | The microphone inserts finalized dictation at the selection in the draft. The waveform starts a spoken conversation. Safari recognizes an utterance, Safari Chat runs the usual turn with its tools and approvals, and the system voice reads the answer before listening again. The panel stops audio on End Voice, a hidden tab, reload or account change. Speech access depends on Safari, the embedding site’s microphone policy and system speech settings. The ChatGPT plan inference route accepts text and excludes audio and transcription. [WebKit speech support](https://webkit.org/blog/11648/new-webkit-features-in-safari-14-1/) · [OpenAI preview limits](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) |
| Webpage gestures | Timed mouse, pen, touch and trackpad sequences allow chords, taps, holds, variable-speed swipes, nested scrolling, drawing with pressure and tilt, and simultaneous contacts that pan, pinch and rotate. HTML drag and drop negotiates an in-page drop. A wheel swipe can send horizontal, vertical and diagonal deltas, smoothly or in individual notches, in pixel, line or page units. Trackpad motion reaches the hovered picture. For pinch, rotation and simultaneous touches, site listeners receive scale, angle and contact lists. On desktop WebKit, a short-lived page listener supplies these properties on scripted events. Other engines can also receive control-wheel pinch. The model can also request tab zoom and history through available Safari tab APIs. Site handlers can reject scripted input. Browser chrome, system gestures, hardware pressure and native file drags require user input. [Pointer Events](https://www.w3.org/TR/pointerevents/) · [Safari gesture events](https://developer.apple.com/documentation/webkitjs/gestureevent/1634533-initgestureevent) · [Safari automation isolation](https://developer.apple.com/documentation/webkit/about-webdriver-for-safari) |
| History | The drawer lists local conversations and drafts for the active connection. Search, edit/retry branching and Markdown export use that local history. Temporary chats live in tab-scoped background memory and survive a normal page navigation. Ending temporary chat returns to regular history. Closing the pane, tab or background, or changing accounts, discards the temporary session. |
| Browser actions | Side chat supports reading the viewport, tab listing, clicking, filling fields, selecting options, changing checkboxes/radio buttons, scrolling, navigation and opening, selecting or closing tabs. Reads and ordinary form interactions can run in another permitted background tab. An approved gesture selects its target in the source window when needed. The background returns to the previous tab after temporary selection and brings the original pane back for an approval when it still owns the selection. An explicit switch leaves the selected tab open there. The panel shows the pending action. Reads of a site opened by this task can request Safari permission for that hostname from the original pane and resume in the existing background tab. Reads expose visible control bounds for motion planning. A path can move the pointer with the button up or hold the primary button through up to 128 waypoints and release. Individual legs, scroll distances and live controls accept numeric speeds in CSS pixels per second. Webpages receive scripted DOM events. OS dialogs, native file dragging and sites that require trusted input need manual interaction. |
| Per-message limits | Both modes start with a 10-minute deadline and 100 browser attempts. Settings → Context and usage adjusts each limit for future turns. An interrupted reply retains its reason when reopened. |
| Website access | Inline prompts offer one-time approval, a remembered grant for a single hostname, all-sites approval, and decline. The composer changes the default. Settings manages allowed and blocked hosts for the active connection in this Safari profile. Blocks also filter tab listings and explicit captures. Desktop plugin requests retain their own approval flow. Safari presents its own system permission prompts. |
| Search and citations | Either mode can locate rendered text in the loaded document beyond the initial viewport, reveal the match, and return an excerpt without typing into the website. Both modes can use opt-in hosted web search, subject to account and model support. Linked citations persist in the conversation. |
| Desktop | An experimental local MCP plugin offers the Safari tools to compatible desktop threads. Approvals return to the originating request. Signed Safari-to-ChatGPT routing still requires live verification. Built-in desktop tab mentions and control from regular cloud conversations require integrations outside this package. |
| Setup and cleanup | A native Mac app contains the Safari extension, account manager and cleanup controls. Browser and native cleanup verify their own storage scopes. User exports, backups and OS records have separate lifetimes. Signing and provisioning are required for live credentials. |
| Other platforms and hosted features | This preview targets macOS. OpenAI’s hosted Voice session, projects, cloud chat history, library/Drive, plugins in the composer and image generation require integrations outside this package. The drawer and attachment menu show supported local actions. |

The browser and native fixture checks cover the interactions described in the validation record. Hosted behavior and signing depend on the installed environment and account.
