# Chrome extension comparison

The reference for this build is OpenAI’s published Chrome side-chat illustration and browser extension guide, inspected November 20, 2026. It shows a compact header, a right-aligned question, an inline work summary, message actions and a bottom composer with an approval control. OpenAI lists side chat for Chrome, Edge, Brave and Vivaldi. Opera connects through the desktop app. Safari Chat implements its own macOS extension using public interfaces. [Official guide and illustration](https://learn.chatgpt.com/docs/chrome-extension) · [Official Chrome listing](https://chromewebstore.google.com/detail/chatgpt/hehggadaopoacecdllhhajmbjkdcmajg)

| Feature | Safari Chat 0.3.6 |
| --- | --- |
| Side chat | A resizable panel reserves space at the right of the originating tab. The toolbar reuses it. Safari exposes the full browser viewport to website media queries and scripts. The pane stays beside the page in narrow windows. Wide content can scroll in the page column. A slow panel offers an in-place retry. When Safari blocks mounting, the toolbar explains the restriction. [Chrome side-panel API compatibility](https://raw.githubusercontent.com/mdn/browser-compat-data/main/webextensions/api/sidePanel.json) |
| Conversation and composer | Right-aligned user messages, plain assistant replies, copy/edit/retry, light/dark/system appearance and a rounded bottom composer. A completed tool-assisted reply shows elapsed time. Approval mode, model and effort are on the chat screen. |
| Longer browser tasks | Safari Chat defaults to 100 browser attempts per message. The composer shows the allowance and offers **Continue** at zero. In side chat the model can start continuous scrolling on a visible page or scroll area, inspect the viewport, change speed and stop. People can take over with the **Stop scrolling** button or direct input on the page. |
| Page and selection | Right-click **Ask Safari Chat** to attach the selection or page for review before sending. Opening or restoring chat shares no page text. |
| Typing and text edits | Side chat can double-click a target or viewport coordinate, focus a writable field, type at the caret and press editing keys. It can select a quoted passage or range and copy, paste, delete or replace that selection. Visible ordinary text may span inline elements. Edits to a paragraph change this copy of the page and can disappear on rerender or reload. The native companion handles plain-text clipboard transfers. |
| Action pointer | A black arrow with a white edge and blue glow follows the cursor design in OpenAI’s published Chrome extension. It marks clicks and copied text and can trace a path across empty space and elements with the button up. Reduce Motion suppresses decorative transitions. The system pointer remains available. [Official Chrome extension](https://chromewebstore.google.com/detail/chatgpt/hehggadaopoacecdllhhajmbjkdcmajg) |
| Tab mentions | Type `@`, filter by tab title or address, then choose with the keyboard or pointer. Use **+ → Add browser tabs** for multiple tabs. Listing accessible tabs reads metadata. Choosing a tab reads its bounded excerpt. |
| Navigation | On refresh and full-document navigation, the dock automatically reopens and reconnects to the running turn, buffered reply, draft and pending approval. Reattachment issues no model request or browser action. The source tab supplies the destination for subsequent reads, subject to website access and fresh element references. Explicitly closing chat stops the task. A browser or background restart ends live execution. |
| Files and captions | Up to six sources total. File selection, drop and paste support UTF-8 text, code and data up to 200 KB per file. Distinct same-name files keep their identities and formatting. Sharing a page can include timestamped captions already exposed by a visible video’s displayed text track. Availability on YouTube depends on its player and the page. PDF, image, audio/video uploads and hosted file management are outside this build. |
| Accounts and models | Browser-hosted ChatGPT OAuth, eligible plan usage or separately named API-key connections. The native app owns selection, refresh, explicit key replacement and sign-out. Selecting a model on the chat screen shows its supported efforts. Model default uses the provider’s default. The panel opens local history and drafts while the model catalog loads. Production account and plan access require live verification. |
| History | Account-separated local history, drafts, recent-chat search and Markdown export. Edit/retry creates a new branch. Concurrent edits preserve separate copies. The public integration does not expose existing ChatGPT cloud chats, projects, library files or memories. |
| Browser actions | Side chat supports reading the viewport, tab listing, clicking, filling fields, selecting options, changing checkboxes/radio buttons, scrolling, navigation and opening/closing tabs. The panel shows the pending action. Reads of a site opened by this task can request Safari permission for that hostname from the original pane and resume in the existing background tab. Reads expose visible control bounds for motion planning. A path can move the pointer with the button up or hold the primary button through up to 128 waypoints and release. Individual legs, scroll distances and live controls accept numeric speeds in CSS pixels per second. Webpages receive scripted DOM events. OS dialogs, native file dragging and sites that require trusted input need manual interaction. |
| Website access | Inline prompts offer one-time approval, a remembered grant for a single hostname, all-sites approval, and decline. The composer changes the default. Settings manages allowed and blocked hosts for the active connection in this Safari profile. Blocks also filter tab listings and explicit captures. Desktop plugin requests retain their own approval flow. Safari presents its own system permission prompts. |
| Search and citations | Opt-in hosted web search through the public Responses API with streamed progress and clickable local citations. Availability depends on model and account. Safari page access has separate approval. |
| Desktop | An experimental local MCP plugin offers the Safari tools to compatible desktop threads. Approvals return to the originating request. Signed Safari-to-ChatGPT routing still requires live verification. Built-in desktop tab mentions and control from regular cloud conversations require integrations outside this package. |
| Setup and cleanup | A native Mac app contains the Safari extension, account manager and cleanup controls. Browser and native cleanup verify their own storage scopes. User exports, backups and OS records have separate lifetimes. Signing and provisioning are required for live credentials. |
| Other platforms and hosted features | This preview targets macOS. Voice, image generation, downloads and iOS/iPadOS are outside its current scope. |

The browser and native fixture checks cover the interactions described in the validation record. Hosted behavior and signing depend on the installed environment and account.
